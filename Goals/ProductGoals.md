# 产品目标

## 总目标

本项目的首要工程目标是用 C++ 重实现 Codex 的 Agent 核心，并把它设计成面向聊天的专用 Agent；不是给 Rust Codex 套一层 QQ 接口。第一阶段先接入 QQ，微信延期。系统接收可信 Channel 事件，选择受控上下文和记忆，通过配置的模型 Provider 执行任务，并把文字或获准的平台动作送回来源渠道。

三种 Provider 协议必须可配置并由同一套 Canonical Model Contract 驱动：

1. OpenAI Responses
2. OpenAI-compatible Chat Completions
3. Anthropic Messages

三个协议适配器、Agent 主循环、记忆/上下文、TUI、Channel Adapter、Core、Storage 和 Windows 平台服务都属于 C++ 运行时。不得把 Rust Codex app-server 作为后台依赖。

## 聊天专用 Agent

- 将入站消息规范化为统一事件，同时保留可信的 Channel、Account、Conversation、Sender、Message 和时间信息。
- 使用自然、稳定、可配置的对话风格；不得冒充某个真实个人或声称自己是人类。
- 能理解持续对话中的要求、偏好和未完成的用户任务，并通过受控的 Context Selector 为当前一轮选取相关信息。
- 记忆分为用户偏好、用户明确确认的事实、Conversation 摘要和 ActiveChatTask；开发 Agent 的任务轨迹与产品聊天记忆完全分离。
- 可使用 Emoji、平台表情/贴纸、反应、拍一拍或类似动作，前提是对应 Channel 明确支持、账号有权限、Core 策略准许且动作符合频率限制。
- 不能完成的动作返回明确 unsupported；不能把“调用已发起”写成“发送成功”，必须取得 ChannelReceipt。
- Shell、主机状态、任意文件访问、任意网络和通用 MCP 不属于聊天 Agent 工具面。未来只加入具体、可审查且经 Core 授权的业务工具。

## Codex 核心重写范围

目标是把聊天 Agent 所需的 Codex Agent 核心行为全部用 C++ 重新实现，包括指令与回合编排、会话状态、上下文选择、三种 Provider、流式事件、工具调用生命周期、记忆读写、取消、错误处理和可恢复状态。完成标准是批准能力都能在 C++ 实现中找到对应模块、合同和验收证据；源码盘点或架构文档本身不算重写完成。

本产品不承接 Codex 的 CLI/IDE 界面、代码编辑工作流、Shell/主机命令拦截、主机状态查询、任意文件访问和通用开发者工具。聊天 Agent 只提供经 Core 授权的业务工具。若未来要恢复被排除的能力，必须新建 ChangeRequest 并重新评估范围。

### 大型上游的能力映射门

Codex 上游的代码行数不是本项目的任务量或验收指标。开始迁移前固定上游仓库、提交和许可证边界，并建立可分片查询的 CodexCapabilityMap。映射单位是子系统、公开行为和可验证能力，不是逐个源文件全文摘要。

聊天产品范围内的每项上游能力必须决定为保留、重设计、移除或暂缓，并映射到目标 C++ 模块、版本化合同、任务 ID、实现状态和验收证据。目标范围内未映射项为零；标为保留或重设计的能力，在对应 C++ 实现及验收证据完成前不得标记为迁移完成。Agent 只读取当前切片需要的上游源码，不把完整 Codex 树或历史记录载入上下文。新上游版本只盘点相关变化。

## Channel 范围

QQ 与未来的微信必须是两个独立 Adapter。当前阶段只处理 QQ；微信不进入本阶段的调研、实现和验收。QQ Bot 与个人 QQ 客户端是不同的身份/能力面，必须依据实际授权路径单独决定。

每个 Adapter 通过 CapabilitySet 声明自己的接收、发送、媒体、贴纸、昵称、反应、拍一拍和主动消息能力。产品不会因为另一个平台支持某动作就推断当前平台也支持。

## 产品记忆与持久化

- 当前消息和短对话窗口在内存中使用。
- 长期记忆按 Channel/Account/Identity/Conversation 范围隔离。
- 用户明确要求记住的偏好、任务约束和进度可形成持久记录。
- 自动提炼的摘要必须带来源和信心/时间信息，检索时作为低优先级上下文。
- 完整原始消息历史是否保留、保留多久、谁可以删除或导出，需要独立隐私决策；默认不无限期保存完整聊天正文。
- 忘记、过期、撤销身份链接应同步处理派生摘要和索引。

## 非目标

- 原样复刻 Codex 的代码生成、IDE、Shell、电脑控制和开发者 UI 功能。
- 通过 SnowLuma、DSH、OneBot 或没有授权的 Hook 作为隐式备用路径。
- 让模型自行决定身份、权限、渠道账号或跨群/跨私聊记忆范围。
- 假设三种 Provider 的每个可选字段都语义等价。只支持通过合同和能力表验证的子集。
- 让 TUI 自己访问数据库、模型网络、DPAPI 或 QQ/微信平台 API。

## 成功条件

- 发布运行时只包含 C++ 产品模块，构建、配置和许可清单可复现。
- 所有纳入当前产品范围的 Codex Agent 能力都映射到 C++ 实现及验收证据；能力地图中仍为待实现的条目不得宣称重写完成。
- 三 Provider 在统一合同下拥有请求映射、流事件、错误、用量、取消和输出上限的契约测试。
- QQ Adapter 明确宣告能力，并按可信身份和 Core policy 执行每一个副作用；微信留待后续阶段单独决策。
- 记忆检索从正确作用域取数据，不能跨身份或渠道意外混合。
- 自研 TUI 在支持的 Windows 终端中处理中文、尺寸变化、粘贴、滚动和退出恢复。
- TUI 与锁定参照库的批准 API/行为映射覆盖率达到 100%，未批准差异为零，并通过差异场景验收。
- 每个发布承诺都对应到提交、构建产物和实际验证证据。
